        def ask(body: AskRequest) -> AskResponse:

  - id: m4
    title: "Leave a trail"
    why: "You give every request a line in the log and an id, so you can follow it later."
    steps:
      - |
        Add a middleware to `app/main.py`. It runs around every request:
        ```python
        import logging
        import time
        import uuid

        from fastapi import FastAPI, Request

        logging.basicConfig(level=settings.log_level, format="%(asctime)s %(levelname)s %(message)s")
        log = logging.getLogger("quest-api")


        @app.middleware("http")
        async def log_requests(request: Request, call_next):
            request_id = uuid.uuid4().hex[:8]
            start = time.perf_counter()
            response = await call_next(request)
            ms = (time.perf_counter() - start) * 1000
            response.headers["X-Request-ID"] = request_id
            log.info("%s %s %s %.0fms id=%s", request.method, request.url.path, response.status_code, ms, request_id)
            return response
        ```
        Imports go at the top, the `logging` lines right after the `settings` import, the middleware after `app = FastAPI(...)`.

Your Python code answers a question, but only you can run it, by hand,
once. This level turns it into a **service**: a program that keeps
running and answers anyone on the network.

<Analogy />

## Request and response

**Every call is one request and one response.**

<Diagram name="request-response" />

A request has a **method** (`GET` to read, `POST` to send), a **path**
(`/ask`), **headers** and sometimes a **body**, usually JSON. The response
brings a **status code**, headers and its own body.

## Your first service

**A whole service is six lines.**

```python
from fastapi import FastAPI
app = FastAPI()

@app.get("/health")
def health():
    return {"status": "ok"}
```

Run `fastapi dev main.py` and open `http://localhost:8000/docs`. FastAPI
wrote that page from your code: every endpoint, ready to try.

## The waiter checks the order

**Describe a good order once. Bad ones never reach your code.**

```python
class AskRequest(BaseModel):
    question: str = Field(min_length=3, max_length=500)
    top_k: int = Field(default=5, ge=1, le=20)
```

A body that does not match gets **422** and a `detail` list that names
the wrong field. Status codes are how you talk back:

<ul class="chips">
  <li class="ok"><b>200</b> OK, here is your answer</li>
  <li class="ok"><b>201</b> Created something new</li>
  <li class="you"><b>400</b> The request makes no sense</li>
  <li class="you"><b>401</b> Who are you? Log in first</li>
  <li class="you"><b>404</b> That does not exist</li>
  <li class="you"><b>422</b> I can't read your order</li>
  <li class="us"><b>500</b> Something broke on our side</li>
</ul>

<Reveal summary="How do I send a 404 myself?">
When you know something is missing, say so on purpose:
`raise HTTPException(status_code=404, detail="Document not found")`.
</Reveal>

## One waiter, many tables: `async def` and `def`

**One waiter serves every table. He must never stand still.**

<Diagram name="event-loop" />

That waiter is the **event loop**. While one order cooks — a database
call, another API — he serves the others. The rule:

- `async def` only when everything slow inside it uses `await`.
- Plain `def` for code that blocks, such as `time.sleep`. FastAPI runs it
  in a thread pool, away from the waiter.

A blocking call inside `async def` freezes every request at once. You
will cause exactly that in "Break it on purpose".

## Settings and a paper trail

**Secrets live in `.env`. Every request leaves one log line.**

Addresses, passwords and keys differ between your laptop and a server, so
they do not belong in the code. `pydantic-settings` reads them from a
`.env` file, and `.env` goes into `.gitignore` on day one.

Use `logging`, not `print`: method, path, status, duration and a
**request id**. When someone says "my request failed at 10:42", the id
takes you to the exact line.

```bash

```

`fastapi dev` listens on `127.0.0.1`: family only, as in Level 2. You are

## What to remember

1. **A model describes a good order.** Bad ones get a 422 that names the field.
2. **Status codes are the waiter's face.** Choose them on purpose.
3. **Never block the waiter.** `async def` with `await`, plain `def` for blocking code.
4. **Secrets live in `.env`, not in git. Every request leaves one log line.**
