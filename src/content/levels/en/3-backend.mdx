  - id: m4
    title: "Leave a trail"
    why: "You give every request a line in the log and an id, so you can follow it later."
    steps:
      - |
        Add a middleware to `app/main.py`. It runs around every request:
        ```python
        import logging
        import time
        import uuid

        from fastapi import FastAPI, Request

        logging.basicConfig(level=settings.log_level, format="%(asctime)s %(levelname)s %(message)s")
        log = logging.getLogger("quest-api")


        @app.middleware("http")
        async def log_requests(request: Request, call_next):
            request_id = uuid.uuid4().hex[:8]
            start = time.perf_counter()
            response = await call_next(request)
            ms = (time.perf_counter() - start) * 1000
            response.headers["X-Request-ID"] = request_id
            log.info("%s %s %s %.0fms id=%s", request.method, request.url.path, response.status_code, ms, request_id)
            return response
        ```
        Keep the imports at the top of the file, the `logging` lines right after `settings` is imported, and the middleware after `app = FastAPI(...)`.

You have Python code that answers a question. Right now only you can run
it, by hand, once. This level turns it into a **service**: a program that
keeps running, waits for requests from anyone on the network and answers
each one, politely, for months.

## Request and response

Every call to a service is one **request** and one **response**. A request
has a **method** (what to do: `GET` to read, `POST` to send something), a
**path** (which endpoint: `/ask`), **headers** (notes about the request)
and sometimes a **body** — the data, usually JSON. The response comes back
with a **status code**, headers and its own body.

<Diagram name="request-response" />

## Your first service

Make a separate toolbox for the project and install FastAPI into it:

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install "fastapi[standard]"
```

Then a whole service is six lines:

```python
from fastapi import FastAPI
app = FastAPI()

@app.get("/health")
def health():
    return {"status": "ok"}
```

Run `fastapi dev main.py` and open `http://localhost:8000/docs`. FastAPI
wrote that page for you from your code: every endpoint, ready to try. You
return a Python dict; the client receives JSON.

## The waiter checks the order

Strangers will send you anything. Instead of checking every field by
hand, you describe what a good order looks like with a Pydantic model:

```python
class AskRequest(BaseModel):
    question: str = Field(min_length=3, max_length=500)
    top_k: int = Field(default=5, ge=1, le=20)
```

A body that does not match never reaches your code. The client gets
**422** and a `detail` list that says exactly which field is wrong and
why.

Status codes are how you talk back. The ones you will use all the time:

| Code | Means |
|---|---|
| 200 | OK, here is your answer |
| 201 | Created something new |
| 400 | The request makes no sense |
| 401 | Who are you? Log in first |
| 404 | That does not exist |
| 422 | I can't read your order |
| 500 | Something broke on our side |

When you know something is missing, say so on purpose:
`raise HTTPException(status_code=404, detail="Document not found")`.

## One waiter, many tables: `async def` and `def`

FastAPI serves requests with an **event loop**: one waiter who runs
between many tables. While one order cooks — a call to a database, to
another API — he serves the others. That only works if he never stands
still.

<Diagram name="event-loop" />

The rule:

- `async def` only when everything slow inside it uses `await`.
- Plain `def` for code that blocks — `time.sleep`, most file and database
  libraries without `async`. FastAPI runs those in a thread pool, away from
  the waiter.

A blocking call inside `async def` freezes every request at once. You will
cause exactly that in "Break it on purpose", so you recognise it forever.

## Settings and a paper trail

Addresses, passwords and keys change between your laptop and a server.
They do not belong in the code. `pydantic-settings` reads them from
environment variables or a `.env` file into a typed `Settings` class. The
`.env` file goes into `.gitignore` on day one. A secret that reaches git
history stays there.

A service also has to tell you what it did. Use `logging`, not `print`:
one line per request with the method, the path, the status, how long it
took, and a **request id**. When someone says "my request failed at
10:42", that id takes you to the exact line.

## Running for real

`fastapi dev` listens on `127.0.0.1` — family only, as you learned in
Level 2. On a server you start it like this:

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

`0.0.0.0`, so callers from the network can reach the door. You are now

## What to remember

1. **A model describes a good order.** Bad ones get a 422 that names the field.
2. **Status codes are the waiter's face.** Choose them on purpose.
3. **Never block the waiter.** `async def` with `await`, plain `def` for blocking code.
4. **Secrets live in `.env`, not in git. Every request leaves one log line.**
