Sooner or later someone says "can you check the server?" and hands you an
address. There is no desktop there, no icons, no mouse — only a blinking
cursor. This level turns that cursor from a wall into a door.

<Analogy />

## Where am I?

The files on a Linux machine form one big tree. It starts at `/`, the
root. Your own folder is `/home/<your name>`, and it has a short nickname:
`~`.

<Diagram name="file-tree" />

Three commands are your eyes and your feet:

```bash
pwd          # which room am I in?
ls -la       # switch on the light: what is here, hidden files too
cd notes     # walk into the room called notes
```

A path that starts with `/` is **absolute**: it works from anywhere, like
a full street address. A path without it is **relative**: it starts from
where you stand. `.` means "this folder" and `..` means "the folder
above", so `cd ..` takes one step up. When a file "is not there", check
`pwd` first. Most of the time the file is fine and you are in another room.

## Reading and finding

To read a file, pick the tool by its size:

- `cat file` prints it all at once — good for short files.
- `less file` lets you scroll; press `q` to leave.
- `head file` and `tail -n 50 file` show the beginning and the last 50 lines.
- `tail -f file` keeps the file open and prints new lines as they arrive.
  That is how you watch a log live.

To find things, you have two hunters: `find . -name "*.py"` looks for
files **by name**, and `grep -rn "text" .` looks for text **inside** files
and tells you the file and the line number.

The real trick is the pipe, `|`. It takes everything one command prints
and hands it to the next one, instead of to your screen:

```bash
ps aux | grep python
```

<Diagram name="pipe" />

`ps aux` lists every process — hundreds of lines. `grep` keeps the few you
care about. Small tools, joined by pipes, do most of the work on a server.

## Who may do what

Run `ls -l` and look at the first column:

```
-rwxr-xr-x 1 student student 112 Mar  3 10:42 ticker.sh
```

<Diagram name="permissions" />

After the type come three groups of `r` (read), `w` (write) and `x`
(run): for the owner, for the group, and for everyone else. A script
needs an `x` before you can start it — `chmod +x script.sh` adds one.
Some actions belong to the whole machine: installing software, editing
files in `/etc`. For those you put `sudo` in front, which means "ask as
the building manager". It will ask for your password. That pause is on
purpose.

## The people in the house: processes

Every running program is a **process** with a number, its **PID**. `ps aux`
lists them all; `htop` shows them live, sorted by how busy they are (`q`
to leave).

- `kill <pid>` asks a process to stop. Most programs tidy up and leave.
- `kill -9 <pid>` forces it. The program gets no chance to clean up, so it
  is the last resort, not the first.
- A command with `&` at the end runs in the background and gives you the
  prompt back.

Here is the catch: background jobs belong to your session. Close the SSH
window and they stop too. For anything long — a training run, a big
download — use **tmux**: a room that stays lit when you leave. You walk
out, the job keeps working, and you come back later to look.

## Is the house healthy?

Four commands answer the questions people ask about a server:

```bash
df -h          # how full is each disk?
du -sh *       # which of these folders is big?
free -h        # how much memory is used, how much is available?
nvidia-smi     # the GPU and who is using it (only if there is one)
```

Most programs that run all the time are **services**, started and watched
by systemd. Two commands tell you their story:

```bash
systemctl status nginx       # is it running? since when?
journalctl -u nginx -f       # its diary, live
```

## The environment and "command not found"

Every shell carries a set of named values, **environment variables**.
`export NAME=value` sets one, `echo $NAME` reads it, `env` lists them all.

One of them is very important: `$PATH`. It is the list of folders where
the shell looks for programs. When you type `python3`, the shell walks
through those folders in order and runs the first match. `command not
found` means no folder on the list had it. `which python3` shows where the
shell found it — or that it found nothing.

## Other machines

`ssh user@host` opens a terminal on another machine. Passwords work, but
engineers use **keys**: a pair of files made on your laptop. The public key
is a lock you can hand out to every server. The private key is the only
key that opens it, and it never leaves your laptop.

A few lines in `~/.ssh/config` turn `ssh student@203.0.113.10` into `ssh
quest`. And `scp file quest:~/` copies a file across.

## What to remember

When you walk into a dark server:

1. **Where am I, and what is here?** → `pwd`, `ls -la`.
2. **Who is home, and are they well?** → `ps aux`, `systemctl status`, `df -h`, `free -h`.
3. **What does the diary say?** → `tail -f`, `journalctl -u`.

below switch them on.
