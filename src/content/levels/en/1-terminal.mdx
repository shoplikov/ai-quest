        ```bash
        mkdir -p ~/quest/level1/{notes,logs,scripts}

      - |

        cd ~/quest/level1
        pwd
        ls -la
        ```

      - |
        Write your first file and read it back:
        ```bash
        echo "hello" > notes/first.txt
        cat notes/first.txt
        ```
      - |
        Add a second line with two arrows and read the file again:
        ```bash
        echo "hello again" >> notes/first.txt
        cat notes/first.txt
        ```
        One `>` replaces the whole file; `>>` adds to the end.
      - |
        Go somewhere else and hunt for the file by its name:
        ```bash
        cd /tmp
        find ~ -name first.txt
        ```
      - |
        Now hunt for the word inside files:
        ```bash
        grep -rn hello ~/quest
        ```
        Read the answer: the path, the line number, then the line itself.
    check: "`find` prints the path to `first.txt`, and `grep` prints the same path with a line number."
  - id: m2
    title: "Watch a log live"
    why: "You start a process, watch what it writes and stop it by its PID."
    steps:
      - |
        Open a new file in the editor:
        ```bash
        nano ~/quest/level1/scripts/ticker.sh
        ```
      - |
        Type this, save with Ctrl+O and Enter, and leave with Ctrl+X:
        ```bash
        #!/usr/bin/env bash
        while true; do echo "$(date +%T) tick" >> ~/quest/level1/logs/ticker.log; sleep 2; done
        ```
      - |
        Make it runnable and check:
        ```bash
        chmod +x ~/quest/level1/scripts/ticker.sh
        ls -l ~/quest/level1/scripts
        ```
        The first column now has `x` in it.
      - |
        Start it in the background with `&`:
        ```bash
        ~/quest/level1/scripts/ticker.sh &
        ```
        The shell prints a job number and a PID, for example `[1] 4242`, and gives you the prompt back.
      - |
        Watch the diary being written. A new line arrives every two seconds.
        ```bash
        tail -f ~/quest/level1/logs/ticker.log
        ```
        Leave with Ctrl+C — that stops `tail`, not the ticker.
      - |
        Find the ticker among all processes:
        ```bash
        ps aux | grep ticker
        ```
        The second column is the PID. One of the lines is the `grep` itself; ignore that one.
      - |
        Ask it to stop, with the PID you found:
        ```bash
        kill <pid>
        ```
      - |
        Run this twice, a few seconds apart:
        ```bash
        tail -n 3 ~/quest/level1/logs/ticker.log
        ```
    check: "After `kill`, the last line of `ticker.log` stays the same no matter how long you wait."

Sooner or later someone says "can you check the server?" and hands you an
address. There is no desktop there, no icons, no mouse — only a blinking
cursor. This level turns that cursor from a wall into a door.

<Analogy />

## Where am I?

**Files form one big tree. `pwd` says where you stand in it.**

<Diagram name="file-tree" />

The tree starts at `/`, the root. Your own folder is `/home/<your name>`,
nicknamed `~`.

```bash
pwd          # which room am I in?
ls -la       # switch on the light: what is here, hidden files too
cd notes     # walk into the room called notes
```

A path that starts with `/` is **absolute**: it works from anywhere. A
path without it is **relative**: it starts from where you stand. File "not
there"? Check `pwd` first.

## Reading and finding

**Pick the reading tool by file size, and join small tools with `|`.**

- `cat file` prints it all — good for short files.
- `less file` lets you scroll; `q` to leave.
- `head file` and `tail -n 50 file` show the beginning and the last 50 lines.
- `tail -f file` prints new lines as they arrive: a log, live.

`find . -name "*.py"` finds files **by name**. `grep -rn "text" .` finds
text **inside** files, with file and line number.

The pipe, `|`, hands what one command prints to the next one:

```bash
ps aux | grep python
```

<Diagram name="pipe" />

## Who may do what

**A script runs only when it has an `x`.**

<Diagram name="permissions" />

Run `ls -l` and look at the first column:

```text
-rwxr-xr-x 1 student student 112 Mar  3 10:42 ticker.sh
```

Three groups of letters: owner, group, everyone else. `chmod +x script.sh`
adds the `x`.

<ul class="chips">
  <li><b>r</b> read</li>
  <li><b>w</b> write</li>
  <li><b>x</b> run</li>
</ul>

<Reveal summary="And what is sudo?">
Installing software or editing files in `/etc` belongs to the whole
machine. Put `sudo` in front: "ask as the building manager". It asks for
your password, and that pause is on purpose.
</Reveal>

## The people in the house: processes

**Every running program has a PID. Background jobs leave when you do.**

`ps aux` lists every **process**; `htop` shows them live (`q` to leave).

- `kill <pid>` asks a process to stop.
- `kill -9 <pid>` forces it, with no chance to clean up. The last resort.
- `&` at the end runs a command in the background.

Close the SSH window and background jobs stop too. For anything long, use
**tmux**: a room that stays lit when you leave.

## Is the house healthy?

**Four commands answer what people ask about a server.**

```bash
df -h          # how full is each disk?
du -sh *       # which of these folders is big?
free -h        # how much memory is used, how much is available?
nvidia-smi     # the GPU and who is using it (only if there is one)
```

Programs that run all the time are **services**, watched by systemd:

```bash
systemctl status nginx       # is it running? since when?
journalctl -u nginx -f       # its diary, live
```

## The environment and "command not found"

**`command not found` means no folder on `$PATH` had it.**

`$PATH` is the list of folders where the shell looks for programs, in
order. `which python3` shows where it found one — or that it found nothing.

<Reveal summary="What else is in the environment?">
`$PATH` is one of the shell's **environment variables**. `export
NAME=value` sets one, `echo $NAME` reads it, `env` lists them all.
</Reveal>

## Other machines

**The public key is a lock you hand out. The private key stays home.**

`ssh user@host` opens a terminal on another machine. Engineers log in
with **keys**: a pair of files made on your laptop.

A few lines in `~/.ssh/config` turn `ssh student@203.0.113.10` into `ssh
quest`. `scp file quest:~/` copies a file across.

## What to remember

1. **Where am I, and what is here?** → `pwd`, `ls -la`.
2. **Who is home, and are they well?** → `ps aux`, `systemctl status`, `df -h`, `free -h`.
3. **What does the diary say?** → `tail -f`, `journalctl -u`.
