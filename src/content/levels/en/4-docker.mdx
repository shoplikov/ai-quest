        ```python
            try:

            except psycopg.OperationalError as error:

                raise HTTPException(status_code=503, detail="database not reachable")

        ```

Your service runs on your laptop. On the server it needs the same Python,
the same packages, the same settings — and something is always slightly
different. Docker's answer is simple to say: don't describe your machine,
ship it.

<Analogy />

## Ship the machine

You write the recipe once, in a `Dockerfile`. `docker build` follows it
and packs an **image**: your code, Python and every package, frozen. `docker
run` takes one box out and opens it: a **container**. You can open as many
as you like from the same image, here or on any server.

<Diagram name="image-vs-container" />

## A Dockerfile, line by line

```dockerfile
FROM python:3.12-slim                  # start from a small box with Python
WORKDIR /app                           # work in /app inside the box
COPY requirements.txt .                # bring the shopping list
RUN pip install -r requirements.txt    # buy everything on it
COPY . .                               # bring your code
CMD ["uvicorn", "app:app", "--host", "0.0.0.0", "--port", "8000"]
```

Each line makes a **layer**, and Docker remembers layers. On the next build
it reuses every layer whose input did not change — until the first one
that did. From there on, everything is built again. So the slow line that
rarely changes (installing packages) goes above the fast line that changes
all the time (your code).

## Build it, run it, look inside

```bash
docker build -t quest-api .                 # follow the recipe
docker run --rm -p 8000:8000 quest-api      # open a box
docker ps                                   # which boxes are running?
docker logs -f <name>                       # what is it saying?
docker exec -it <name> sh                   # open the box and look inside
```

A `.dockerignore` file keeps things out of the box: `.venv` (the box has
its own packages), `.git`, caches, and `.env` with your secrets. Smaller
boxes build faster and leak nothing. The `-slim` base image helps too.

## Ports, one floor deeper

`-p 8000:8000` cuts a door in the box. **Left is your machine, right is the
box.** `-p 8080:8000` means "door 8080 on my machine leads to door 8000 in
the box".

And Level 2 comes back: inside the box, `127.0.0.1` is the box itself.
Docker's door brings visitors in from outside, so the app in the box must
listen on `0.0.0.0`. Switch it to Docker mode:

## Data lives on a shelf

Containers are disposable. You remove one, and everything written inside
it is gone. That is a feature: a fresh box is always clean. But a database
must not forget. Anything worth keeping goes into a **volume**, a shelf in
the real kitchen that survives the box.

## Compose: boxes that know each other

A real service is several boxes: the API, a database, later a cache.
`compose.yaml` describes them all, and one command starts them together:

```yaml
services:
  api:
    build: .
    ports: ["8000:8000"]
    env_file: .env
    depends_on:
      db:
        condition: service_healthy
  db:
    image: postgres:17
    environment:
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
    volumes: ["pgdata:/var/lib/postgresql/data"]
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 5s
      retries: 10
volumes:
  pgdata:
```

Compose puts the boxes in one network where they find each other **by
service name**. The API reaches the database at `db:5432` — never
`localhost:5432`, which is the API's own box.

<Diagram name="compose-network" />

Everyday commands: `docker compose up -d --build` (start, rebuilding what
changed), `docker compose logs -f api`, `docker compose ps`, `docker
compose exec api sh`, `docker compose down`.

> ⚠️ `docker compose down -v` also deletes the volumes — your database
> data with them. On a real project, stop and read the command twice.

## What to remember

1. **Image = recipe and packed box. Container = one opened box.**
2. **Slow, stable lines first; your code last.** Then rebuilds take seconds.
3. **Inside a box, `localhost` is the box.** Listen on `0.0.0.0`; call other boxes by service name.
4. **Data worth keeping lives in a volume.** And `down -v` deletes it.
