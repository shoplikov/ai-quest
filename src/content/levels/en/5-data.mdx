        ```python
        from pgvector.sqlalchemy import Vector
        from sqlalchemy import ForeignKey, Index, String, Text, func
        from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column


        class Base(DeclarativeBase):
            pass


        class Document(Base):
            __tablename__ = "documents"

            id: Mapped[int] = mapped_column(primary_key=True)
            title: Mapped[str] = mapped_column(String(200))
            source: Mapped[str] = mapped_column(String(500))
            created_at: Mapped[datetime] = mapped_column(server_default=func.now())


        class Chunk(Base):
            __tablename__ = "chunks"

            id: Mapped[int] = mapped_column(primary_key=True)
            document_id: Mapped[int] = mapped_column(ForeignKey("documents.id"))
            content: Mapped[str] = mapped_column(Text)
            embedding = mapped_column(Vector(384))

            __table_args__ = (
                Index(
                    "chunks_embedding_idx",
                    "embedding",
                    postgresql_using="hnsw",
                    postgresql_ops={"embedding": "vector_cosine_ops"},
                ),
            )
        ```

        Write `app/services/embeddings.py`. This model expects `passage: ` in front of stored texts and `query: ` in front of questions:
        ```python
        from functools import lru_cache

        MODEL_NAME = "intfloat/multilingual-e5-small"


        @lru_cache
        def get_model():
            # Imported here, so the app and its tests start without loading the model.
            from sentence_transformers import SentenceTransformer

            return SentenceTransformer(MODEL_NAME)


        def embed_passages(texts: list[str]) -> list[list[float]]:
            vectors = get_model().encode([f"passage: {t}" for t in texts], normalize_embeddings=True)
            return vectors.tolist()


        def embed_query(text: str) -> list[float]:
            return get_model().encode(f"query: {text}", normalize_embeddings=True).tolist()
        ```

        ```python
        @router.get("/search")
        def search(q: str = Query(min_length=2, max_length=200), k: int = Query(default=5, ge=1, le=20)):
            key = f"search:{k}:{q}"
            cached = cache.get(key)
            if cached is not None:
                log.info("cache hit %s", key)
                return json.loads(cached)
            log.info("cache miss %s", key)

            vector = embed_query(q)
            distance = Chunk.embedding.cosine_distance(vector).label("distance")
            with SessionLocal() as session:
                rows = session.execute(select(Chunk.id, Chunk.content, distance).order_by(distance).limit(k)).all()
            results = [{"id": r.id, "content": r.content, "distance": round(r.distance, 3)} for r in rows]

            cache.set(key, json.dumps(results), ex=60)
            return results
        ```

So far `quest-api` forgets everything the moment it answers. A real
service has to remember: the documents it knows, what they mean, and

and teaches you to keep them safe.

## Tables, rows and keys

Postgres keeps data in **tables**. A table has columns with fixed types,
and rows that follow them. Every row has a **primary key**, usually `id`,
that never changes. A column that holds another table's id is a **foreign
key**: it is how a chunk says "I belong to document 2".

You talk to Postgres in `psql`. Four commands to start: `\l` lists
databases, `\dt` lists tables, `\d documents` describes one table, `\q`
leaves.

## SQL you need every week

```sql
SELECT title, source FROM documents WHERE source = 'handbook.md' ORDER BY title LIMIT 10;
INSERT INTO documents (title, source) VALUES ('Refunds', 'handbook.md');
UPDATE documents SET title = 'Refund rules' WHERE id = 2;
SELECT source, COUNT(*) FROM documents GROUP BY source;
```

Read `UPDATE` twice before you press Enter. **Without `WHERE` it changes
every row in the table.** The same goes for `DELETE`.

A `JOIN` puts two tables side by side, matching rows by a key:

```sql
SELECT documents.title, chunks.content
FROM chunks JOIN documents ON documents.id = chunks.document_id;
```

## From Python, safely

In the service you use SQLAlchemy 2 with the psycopg 3 driver. The address
comes from settings, never from code. The engine keeps a **pool**: a few
open connections that requests borrow and give back, instead of opening a
new one each time.

And one rule without exceptions: **values travel as parameters, never
glued into the SQL.**

```python
# Never: the input becomes part of the SQL
session.execute(text(f"SELECT * FROM documents WHERE title = '{title}'"))
# Always: the input stays a value
session.execute(text("SELECT * FROM documents WHERE title = :title"), {"title": title})
```

With the first line, a title like `x' OR '1'='1` returns every row. That
is SQL injection, and parameters make it impossible.

## Migrations and backups

Your tables are code too. **Migrations** are small numbered steps that
build the schema, kept in git. Alembic writes them for you from your
models (`alembic revision --autogenerate -m "…"`) and applies them
(`alembic upgrade head`). Every database — your laptop, a colleague's, the
server — gets the same schema the same way.

<Diagram name="migrations-timeline" />

The other half of keeping data safe is the backup. `pg_dump -Fc` writes a
database to one file; `pg_restore` brings it back. **A backup you have
never restored is a hope, not a backup.** In Mission 5 you restore one.

## Indexes: the library catalogue

Ask Postgres how it found your answer:

```sql
EXPLAIN ANALYZE SELECT * FROM documents WHERE source = 'handbook.md';
```

`Seq Scan` means it read every row — every book on every shelf. `Index
Scan` means it used the catalogue. An index on the column you filter by
turns seconds into milliseconds. Indexes cost a little on every write, so
you add them where you search, not everywhere.

## Vectors: shelves by meaning

An **embedding** is a list of numbers that places a text on a map of
meaning. Texts that mean similar things land close together, even when
they share no words.

<Diagram name="meaning-map" />

pgvector stores these lists in a column and measures distances:

```sql
CREATE EXTENSION IF NOT EXISTS vector;
CREATE TABLE chunks (
  id bigserial PRIMARY KEY,
  document_id bigint NOT NULL,
  content text NOT NULL,
  embedding vector(384)
);
SELECT id, content FROM chunks ORDER BY embedding <=> :query_vec LIMIT 5;
CREATE INDEX ON chunks USING hnsw (embedding vector_cosine_ops);
```

`<=>` is cosine distance: smaller means closer in meaning. The `384` is
fixed by your model, `intfloat/multilingual-e5-small`. In compose you use
the image `pgvector/pgvector:pg17`: Postgres with pgvector already inside.

## Redis: sticky notes

Some work is slow and gets asked for again and again. Redis keeps the
answer for a while:

```
SET search:money-back "[…]" EX 60
GET search:money-back
TTL search:money-back
```

The pattern is called **cache-aside**: look at the sticky note first; if
it is there, answer at once; if not, do the real work and stick the answer
up for 60 seconds.

## What to remember

1. **Postgres is the source of truth.** The schema changes only through migrations.
2. **Parameters, always.** And `UPDATE` without `WHERE` changes every row.
3. **`Seq Scan` on a big table? Look for a missing index.**
4. **Vectors live on one model's map.** New model, new embeddings.
5. **Redis only holds what you can rebuild. Backups count only once restored.**
