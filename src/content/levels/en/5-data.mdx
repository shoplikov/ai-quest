        ```python
        from datetime import datetime

        from pgvector.sqlalchemy import Vector
        from sqlalchemy import ForeignKey, Index, String, Text, func
        from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column


        class Base(DeclarativeBase):
            pass


        class Document(Base):
            __tablename__ = "documents"

            id: Mapped[int] = mapped_column(primary_key=True)
            title: Mapped[str] = mapped_column(String(200))
            source: Mapped[str] = mapped_column(String(500))
            created_at: Mapped[datetime] = mapped_column(server_default=func.now())


        class Chunk(Base):
            __tablename__ = "chunks"

            id: Mapped[int] = mapped_column(primary_key=True)
            document_id: Mapped[int] = mapped_column(ForeignKey("documents.id"))
            content: Mapped[str] = mapped_column(Text)
            embedding = mapped_column(Vector(384))

            __table_args__ = (
                Index(
                    "chunks_embedding_idx",
                    "embedding",
                    postgresql_using="hnsw",
                    postgresql_ops={"embedding": "vector_cosine_ops"},
                ),
            )
        ```

      - |
        Write `app/services/embeddings.py`:
        ```python
        from functools import lru_cache

        MODEL_NAME = "intfloat/multilingual-e5-small"


        @lru_cache
        def get_model():
            # Imported here, so the app and its tests start without loading the model.
            from sentence_transformers import SentenceTransformer

            return SentenceTransformer(MODEL_NAME)


        def embed_passages(texts: list[str]) -> list[list[float]]:
            vectors = get_model().encode([f"passage: {t}" for t in texts], normalize_embeddings=True)
            return vectors.tolist()


        def embed_query(text: str) -> list[float]:
            return get_model().encode(f"query: {text}", normalize_embeddings=True).tolist()
        ```
        This model expects `passage: ` in front of stored texts and `query: ` in front of questions.

        ```python
        SENTENCES = [
            "The café opens at 8 in the morning and closes at 9 in the evening.",
            "On Mondays the café is closed for cleaning.",
            "Guests who are unhappy with a drink can ask for a refund within 14 days.",
            "Keep the receipt; we need it for every refund.",

            "Free Wi-Fi: the password is on the board next to the till.",
            "Cakes are delivered every morning at 7.",
            "Unsold sandwiches go to the food bank at closing time.",
            "Every new barista shadows a colleague for three shifts.",
            "Holiday requests go in the calendar at least two weeks ahead.",
            "If the card machine fails, take cash and write the time down.",

            "Clean the coffee machine at the end of every shift.",
            "Tips are shared equally at the end of the week.",
            "The music is turned down after 6 in the evening.",
        ```

      - |
        Write `app/routers/search.py`:
        ```python
        from fastapi import APIRouter, Query
        from sqlalchemy import select

        from app.db import SessionLocal
        from app.models import Chunk
        from app.services.embeddings import embed_query

        router = APIRouter()


        @router.get("/search")
        def search(q: str = Query(min_length=2, max_length=200), k: int = Query(default=5, ge=1, le=20)):
            vector = embed_query(q)
            distance = Chunk.embedding.cosine_distance(vector).label("distance")
            with SessionLocal() as session:
                rows = session.execute(select(Chunk.id, Chunk.content, distance).order_by(distance).limit(k)).all()
            return [{"id": r.id, "content": r.content, "distance": round(r.distance, 3)} for r in rows]
        ```

        In the same file, change `search`. It looks at the sticky note before doing the work:
        ```python
        @router.get("/search")
        def search(q: str = Query(min_length=2, max_length=200), k: int = Query(default=5, ge=1, le=20)):
            key = f"search:{k}:{q}"
            cached = cache.get(key)
            if cached is not None:
                log.info("cache hit %s", key)
                return json.loads(cached)
            log.info("cache miss %s", key)

            vector = embed_query(q)
            distance = Chunk.embedding.cosine_distance(vector).label("distance")
            with SessionLocal() as session:
                rows = session.execute(select(Chunk.id, Chunk.content, distance).order_by(distance).limit(k)).all()
            results = [{"id": r.id, "content": r.content, "distance": round(r.distance, 3)} for r in rows]

            cache.set(key, json.dumps(results), ex=60)
            return results
        ```

breaks:
  - id: b1
    title: "Wrong key to the library"
    do: |
      In `.env`, change `POSTGRES_PASSWORD` and the password inside `DATABASE_URL` to `new-secret`. Then:
      ```bash
      docker compose up -d
      curl -s localhost:8000/ready
      docker compose logs api | tail -3
      ```
    see: "FATAL:  password authentication failed for user \"postgres\""
    why: "`POSTGRES_PASSWORD` is used only once: when the database is created in an empty volume. Your volume already holds a database with the old password, and changing the variable later does not change it."
    fix: "Put the old password back and run `docker compose up -d`. To really change it, change it inside the database first (`ALTER USER postgres PASSWORD '…';` in `psql`), then in `.env`."
  - id: b2
    title: "Wrong shape"
    do: |
      In `psql`, store a vector with three numbers:
      ```sql
      INSERT INTO chunks (document_id, content, embedding) VALUES (1, 'tiny', '[1,2,3]');
      ```
    see: "ERROR:  expected 384 dimensions, not 3"
    why: "The column fixes the size: `vector(384)`, because your model makes 384 numbers. A different model makes vectors of a different size, on a different map. Switching models means re-embedding everything."
    fix: "Store vectors from the same model as the column. Nothing was saved, so there is nothing to undo."
  - id: b3
    title: "Read every book"
    do: |
      In `psql`, add 200,000 rows, update the statistics, then ask how Postgres finds one row:
      ```sql
      INSERT INTO documents (title, source) SELECT 'Document ' || n, 'source-' || n FROM generate_series(1, 200000) AS n;
      ANALYZE documents;
      EXPLAIN ANALYZE SELECT * FROM documents WHERE source = 'source-123456';
      ```
    see: "Seq Scan on documents"
    why: "With no index on `source`, Postgres reads every row to find one — every book on every shelf. (On a bigger machine it says `Parallel Seq Scan`: several readers, still every book.) Look at `Execution Time`."
    fix: "Build the catalogue: `CREATE INDEX ON documents (source);` and run the same `EXPLAIN ANALYZE`. Now it says `Index Scan using documents_source_idx`, and the time drops by a hundred times or more. Clean up: `DELETE FROM documents WHERE source LIKE 'source-%';` and `DROP INDEX documents_source_idx;`."

    meaning: "Wrong host — `localhost` inside a container — or the database is not ready yet."
    firstMove: "Use the service name `db`; give `db` a healthcheck and the API `depends_on` it."
  - error: "password authentication failed for user \"postgres\""
    meaning: "The password differs from the one the database was created with."
    firstMove: "Check `.env`; on a toy database you may recreate the volume."
  - error: "relation \"chunks\" does not exist"
    meaning: "The migration was not applied, or you are connected to another database."
    firstMove: "`alembic current`, and `\\dt` in `psql`"
  - error: "type \"vector\" does not exist"
    meaning: "The pgvector extension was never created in this database."
    firstMove: "`op.execute(\"CREATE EXTENSION IF NOT EXISTS vector\")` at the start of the first migration."
  - error: "NameError: name 'pgvector' is not defined"
    meaning: "Autogenerate wrote a pgvector type into the migration but no import."
    firstMove: "Add `import pgvector.sqlalchemy` to the migration file."
  - error: "sorry, too many clients already"
    meaning: "Connections were opened and never given back. Like library books, except this librarian counts."
    firstMove: "One engine with a pool for the whole app; close every session (`with SessionLocal() as session:`)."

    meaning: "You are inserting something that already exists. The database has seen this one before and is not impressed."
    firstMove: "Decide on purpose: skip it, update it (`ON CONFLICT`), or fix the input."
  - error: "failed to resolve host 'db'"
    meaning: "You are running on your laptop, outside the compose network, where the name `db` means nothing. (`psql` says `could not translate host name \"db\"`.)"
    firstMove: "From the laptop use `localhost` and the published port."

  - q: "A query is slow, and `EXPLAIN` shows `Seq Scan` on 5 million rows. What do you do?"
    options:
      - "Add an index on the column you filter by"
      - "Add more RAM"
      - "Restart the database"
    answer: 0
    why: "`Seq Scan` means reading every row. An index is the catalogue that takes Postgres straight to the right shelf."
  - q: "You switched to an embedding model with 1024 dimensions instead of 384. What has to happen?"
    options:
      - "Change the column and re-embed all documents"
      - "Nothing"
      - "Only new documents need the new model"

    why: "Old and new vectors live on different maps. You cannot measure the distance between a point on one map and a point on another."

      - "The only copy of user documents"
      - "Your migrations"
    answer: 0
    why: "Sticky notes are allowed to fall off. Keep in Redis only what you can rebuild. Nobody keeps a passport on a sticky note. Well. Almost nobody."
  - q: "A colleague builds SQL with an f-string from user input. What is wrong?"

      - "It allows SQL injection; use query parameters"
      - "It is slow"
      - "Nothing — it is fine in Python"
    answer: 0

So far `quest-api` forgets everything the moment it answers. This level

## Tables, rows and keys

**A table is a shelf with rules. Keys link the shelves.**

Every row has a **primary key**, usually `id`, that never changes. A
**foreign key** holds another table's id: it is how a chunk says "I belong
to document 2".

Four `psql` commands to start:

<ul class="chips">
  <li><b>\l</b> lists databases</li>
  <li><b>\dt</b> lists tables</li>
  <li><b>\d documents</b> describes one table</li>
  <li><b>\q</b> leaves</li>
</ul>

## SQL you need every week

**Four verbs do the work. `JOIN` puts two tables side by side.**

<Diagram name="join" />

```sql
SELECT title, source FROM documents WHERE source = 'handbook.md' ORDER BY title LIMIT 10;
INSERT INTO documents (title, source) VALUES ('Refunds', 'handbook.md');
UPDATE documents SET title = 'Refund rules' WHERE id = 2;
SELECT source, COUNT(*) FROM documents GROUP BY source;
```

**Without `WHERE`, `UPDATE` changes every row in the table.** So does
`DELETE`.

A `JOIN` matches rows by a key:

```sql
SELECT documents.title, chunks.content
FROM chunks JOIN documents ON documents.id = chunks.document_id;
```

## From Python, safely

**Values travel as parameters, never glued into the SQL.**

```python
# Never: the input becomes part of the SQL
session.execute(text(f"SELECT * FROM documents WHERE title = '{title}'"))
# Always: the input stays a value
session.execute(text("SELECT * FROM documents WHERE title = :title"), {"title": title})
```

With the first line, a title like `x' OR '1'='1` returns every row: SQL
injection. Parameters make it impossible.

<Reveal summary="What is a connection pool?">
The SQLAlchemy engine keeps a **pool**: a few open connections that
requests borrow and give back, instead of opening a new one each time.
</Reveal>

## Migrations and backups

**Your tables are code too: migrations build them, step by step.**

<Diagram name="migrations-timeline" />

**Migrations** are small numbered steps, kept in git. Alembic writes them
from your models, so every database gets the same schema the same way.

`pg_dump -Fc` writes a database to one file; `pg_restore` brings it back.
**A backup you have never restored is a hope, not a backup.**

## Indexes: the library catalogue

**An index is the catalogue. Without it, Postgres reads every book.**

```sql
EXPLAIN ANALYZE SELECT * FROM documents WHERE source = 'handbook.md';
```

<ul class="chips">
  <li class="you"><b>Seq Scan</b> it read every row</li>
  <li class="ok"><b>Index Scan</b> it used the catalogue</li>
</ul>

An index on the column you filter by turns seconds into milliseconds.

<Reveal summary="Why not put an index on every column?">
Indexes cost a little on every write, so you add them where you search,
not everywhere.
</Reveal>

## Vectors: shelves by meaning

**An embedding places a text on a map of meaning.**

<Diagram name="meaning-map" />

An **embedding** is a list of numbers. Similar meanings land close
together, even with no shared words. pgvector stores the lists and
measures distances:

```sql
CREATE EXTENSION IF NOT EXISTS vector;
CREATE TABLE chunks (
  id bigserial PRIMARY KEY,
  document_id bigint NOT NULL,
  content text NOT NULL,
  embedding vector(384)
);
SELECT id, content FROM chunks ORDER BY embedding <=> :query_vec LIMIT 5;
CREATE INDEX ON chunks USING hnsw (embedding vector_cosine_ops);
```

`<=>` is cosine distance: smaller means closer in meaning. The `384` is
fixed by your model, `intfloat/multilingual-e5-small`.

## Redis: sticky notes

**Look at the sticky note first. Do the real work only on a miss.**

<Diagram name="cache-aside" />

Redis keeps the answer to slow, repeated work for a while:

```
SET search:money-back "[…]" EX 60
GET search:money-back
TTL search:money-back
```

This is **cache-aside**: on a miss, do the work and stick the answer up
for 60 seconds.

## What to remember

1. **Postgres is the source of truth.** The schema changes only through migrations.
2. **Parameters, always.** And `UPDATE` without `WHERE` changes every row.
3. **`Seq Scan` on a big table? Look for a missing index.**
4. **Vectors live on one model's map.** New model, new embeddings.
5. **Redis only holds what you can rebuild. Backups count only once restored.**
