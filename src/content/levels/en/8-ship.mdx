        ```python
            except OperationalError as error:
        ```

    why: "Every log line carries the request id, so one `grep` tells one request's whole story."
    steps:
      - |
        Write `app/logs.py`. It prints every log line as one JSON object and remembers the id of the current request:
        ```python
        import json
        import logging
        import time
        from contextlib import contextmanager
        from contextvars import ContextVar

        request_id: ContextVar[str] = ContextVar("request_id", default="-")
        log = logging.getLogger("quest-api")


        class JsonFormatter(logging.Formatter):
            def format(self, record: logging.LogRecord) -> str:
                line = {
                    "time": self.formatTime(record),
                    "level": record.levelname,
                    "request_id": request_id.get(),
                    "message": record.getMessage(),
                }
                line.update(getattr(record, "data", {}))
                if record.exc_info:
                    line["error"] = self.formatException(record.exc_info)
                return json.dumps(line, ensure_ascii=False)


        def setup_logging(level: str) -> None:
            handler = logging.StreamHandler()
            handler.setFormatter(JsonFormatter())
            logging.basicConfig(level=level, handlers=[handler], force=True)


        @contextmanager
        def timed(stage: str):
            """Log how long one stage of a request took."""
            start = time.perf_counter()
            try:
                yield
            finally:
                ms = round((time.perf_counter() - start) * 1000)
                log.info("stage", extra={"data": {"stage": stage, "ms": ms}})
        ```
        A `ContextVar` is a variable with one value per request: two requests handled at the same time each see their own id.
      - |
        In `app/main.py`, import `setup_logging` and `request_id` from `app.logs`. Then replace the `logging.basicConfig(...)` line with:

      - |
        Let the middleware set the id before the request runs:
        ```python
        @app.middleware("http")
        async def log_requests(request: Request, call_next):
            rid = uuid.uuid4().hex[:8]
            request_id.set(rid)
            start = time.perf_counter()
            response = await call_next(request)
            ms = round((time.perf_counter() - start) * 1000)
            response.headers["X-Request-ID"] = rid
            log.info(
                "request",
                extra={"data": {"method": request.method, "path": request.url.path, "status": response.status_code, "ms": ms}},
            )
            return response
        ```
        Everything in `data` becomes its own JSON field. Your older `log.info("…")` calls keep working: their text lands in `message`, and they get the request id for free.

        Now load. Write `scripts/load.py` — 50 questions, five at a time:
        ```python
        import statistics
        import sys
        import time
        from concurrent.futures import ThreadPoolExecutor

        import httpx

        URL = sys.argv[1] if len(sys.argv) > 1 else "http://localhost:8000"
        QUESTIONS = [
            "When does the café open?",
            "Can I get my money back after three weeks?",
            "Who gets order KZ-4471?",
            "Does oat milk cost extra?",
            "Do you have parking for guests?",
        ]


        def ask(i: int) -> tuple[float, bool]:
            start = time.perf_counter()
            try:
                response = httpx.post(f"{URL}/ask", json={"question": QUESTIONS[i % len(QUESTIONS)]}, timeout=120)
                ok = response.status_code == 200
            except httpx.HTTPError:
                ok = False
            return time.perf_counter() - start, ok


        with ThreadPoolExecutor(max_workers=5) as pool:
            results = list(pool.map(ask, range(50)))

        times = sorted(seconds for seconds, _ in results)
        errors = sum(not ok for _, ok in results)
        p50 = statistics.median(times)
        p95 = statistics.quantiles(times, n=20)[-1]
        print(f"p50 {p50:.1f}s  p95 {p95:.1f}s  errors {errors}/{len(results)}")
        ```

        ```bash
        ssh "$SERVER" "cd quest-api && QUEST_TAG=$TAG docker compose up -d --no-build && echo 'rollback to $TAG' >> deploys.log"
        ```

## Same code, different places

**The code is the same everywhere. Only the environment variables differ.**

Addresses, passwords and model names live in **environment variables**.
If a required one is missing, the service refuses to start and says
which. Secrets never go into git, because git never forgets.

## Alive, or ready?

**A service can be alive and useless at the same time.**

<Diagram name="health-vs-ready" />

<ul class="chips">
  <li><b>/health</b> Is the process alive?</li>
  <li><b>/ready</b> Can I do my job: are the database and the model reachable?</li>
</ul>

<Reveal summary="How does Compose use these answers?">
A `healthcheck` tells Compose how a box is doing, and
`restart: unless-stopped` starts a box again after a crash or a reboot.
</Reveal>

## Logs you can search

**One JSON line per event, and a request id in every line.**

A log is a diary: only useful if you can find the page. With the
**request id**, one `grep` shows one request's whole way through the
service.

## The four numbers

**Count four things. For latency, look at p95, never at the average.**

<Diagram name="p95" />

<ul class="chips">
  <li><b>Request rate</b> how busy</li>
  <li><b>Error rate</b> how broken</li>
  <li><b>Latency</b> how slow</li>
  <li><b>Tokens per request</b> how expensive, for LLM services</li>
</ul>

**p50** is the typical request. **p95** is the wait of the unluckiest one
in twenty.

<Reveal summary="Who reads these numbers?">
Usually Prometheus: it reads your `/metrics` page every few seconds and
draws the graphs.
</Reveal>

## The robot reviewer

**CI runs the same checks on every push. Red means: do not deploy.**

**CI** — continuous integration — runs the linter, the tests and the
image build. It is never tired and never in a hurry.

## Deploy and rollback

**Tag every image with its commit. A rollback starts the previous tag.**

<Diagram name="deploy-rollback" />

A deploy has three steps: build an image, ship it, start it. A
**rollback** is yesterday's menu: already printed, ready in a minute.
Practise it before you need it.

## When it breaks

**First make it work again. Only then find out why.**

Roll back or restart first. Afterwards, write a short, blameless note:
what happened, who was affected, the cause, what we change. It asks what
let the mistake through, never who made it.

## The runbook

**One page, written for a tired person at night.**

It says how to deploy, how to roll back, where the logs are, what each
alert means and who to call. One day that tired person will be you.

## A real example

**This website started out deployed exactly this way:** one small
server, Docker, `scripts/deploy.sh`. Its repository still has
`scripts/deploy.sh`, a `.github/workflows/` folder and
`docs/SETUP-GITHUB-AWS.md` — after this level, you can read all three.

Then it moved. The site is only plain files — no backend, no database — so
a server running all day was paying rent for nothing. Now a version tag
runs `.github/workflows/deploy.yml`, which builds the files and hands them
to GitHub Pages. Same checks, same tags, no server. Pick the smallest thing
that does the job.

The journey from Level 2 once more. Under "Where would it break?", try
each place: each now has a log line and a health check.

## What to remember

1. **Alive is not ready.** `/health` and `/ready` answer different questions.
2. **One request, one id, one `grep`.**
3. **Look at p95.** The average hides the people who wait.
4. **Tag every image with its commit.** Then a rollback is one command.
5. **First make it work, then find out why.**
