        ```python
        from datetime import datetime

        from pgvector.sqlalchemy import Vector
        from sqlalchemy import ForeignKey, Index, String, Text, func
        from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column


        class Base(DeclarativeBase):
            pass


        class Document(Base):
            __tablename__ = "documents"

            id: Mapped[int] = mapped_column(primary_key=True)
            title: Mapped[str] = mapped_column(String(200))
            source: Mapped[str] = mapped_column(String(500))
            created_at: Mapped[datetime] = mapped_column(server_default=func.now())


        class Chunk(Base):
            __tablename__ = "chunks"

            id: Mapped[int] = mapped_column(primary_key=True)
            document_id: Mapped[int] = mapped_column(ForeignKey("documents.id"))
            content: Mapped[str] = mapped_column(Text)
            embedding = mapped_column(Vector(384))

            __table_args__ = (
                Index(
                    "chunks_embedding_idx",
                    "embedding",
                    postgresql_using="hnsw",
                    postgresql_ops={"embedding": "vector_cosine_ops"},
                ),
            )
        ```

        Напиши `app/services/embeddings.py`. Эта модель ждёт `passage: ` перед сохраняемыми текстами и `query: ` перед вопросами:
        ```python
        from functools import lru_cache

        MODEL_NAME = "intfloat/multilingual-e5-small"


        @lru_cache
        def get_model():
            # Импорт здесь, чтобы приложение и тесты запускались, не загружая модель.
            from sentence_transformers import SentenceTransformer

            return SentenceTransformer(MODEL_NAME)


        def embed_passages(texts: list[str]) -> list[list[float]]:
            vectors = get_model().encode([f"passage: {t}" for t in texts], normalize_embeddings=True)
            return vectors.tolist()


        def embed_query(text: str) -> list[float]:
            return get_model().encode(f"query: {text}", normalize_embeddings=True).tolist()
        ```

        ```python
        from sqlalchemy import select

        from app.db import SessionLocal
        from app.models import Chunk
        from app.services.embeddings import embed_query

        router = APIRouter()


        @router.get("/search")
        ```

        ```python
        @router.get("/search")
        def search(q: str = Query(min_length=2, max_length=200), k: int = Query(default=5, ge=1, le=20)):
            key = f"search:{k}:{q}"
            cached = cache.get(key)
            if cached is not None:
                log.info("cache hit %s", key)
                return json.loads(cached)
            log.info("cache miss %s", key)

            vector = embed_query(q)
            distance = Chunk.embedding.cosine_distance(vector).label("distance")
            with SessionLocal() as session:
                rows = session.execute(select(Chunk.id, Chunk.content, distance).order_by(distance).limit(k)).all()
            results = [{"id": r.id, "content": r.content, "distance": round(r.distance, 3)} for r in rows]

            cache.set(key, json.dumps(results), ex=60)
            return results
        ```

## Таблицы, строки и ключи

Postgres хранит данные в **таблицах**. У таблицы есть колонки с
фиксированными типами и строки, которые им подчиняются. У каждой строки
есть **первичный ключ** (primary key), обычно `id`, который никогда не
меняется. Колонка, где хранится id из другой таблицы, — **внешний ключ**
(foreign key): так чанк говорит «я принадлежу документу 2».

С Postgres разговаривают в `psql`. Четыре команды для начала: `\l` — список
баз данных, `\dt` — список таблиц, `\d documents` — описание одной таблицы,
`\q` — выход.

## SQL, который нужен каждую неделю

```sql
SELECT title, source FROM documents WHERE source = 'handbook.md' ORDER BY title LIMIT 10;
INSERT INTO documents (title, source) VALUES ('Refunds', 'handbook.md');
UPDATE documents SET title = 'Refund rules' WHERE id = 2;
SELECT source, COUNT(*) FROM documents GROUP BY source;
```

Прочитай `UPDATE` дважды, прежде чем нажать Enter. **Без `WHERE` он меняет
все строки в таблице.** С `DELETE` то же самое.

`JOIN` ставит две таблицы рядом и сопоставляет строки по ключу:

```sql
SELECT documents.title, chunks.content
FROM chunks JOIN documents ON documents.id = chunks.document_id;
```

## Из Python — безопасно

В сервисе ты работаешь через SQLAlchemy 2 с драйвером psycopg 3. Адрес базы
приходит из настроек, а не из кода. Движок держит **пул**: несколько
открытых соединений, которые запросы берут и возвращают, вместо того чтобы
каждый раз открывать новое.

И одно правило без исключений: **значения передаются параметрами и никогда
не склеиваются с SQL.**

```python
# Никогда: ввод становится частью SQL
session.execute(text(f"SELECT * FROM documents WHERE title = '{title}'"))
# Всегда: ввод остаётся значением
session.execute(text("SELECT * FROM documents WHERE title = :title"), {"title": title})
```

В первой строке название вроде `x' OR '1'='1` вернёт все строки. Это и есть
SQL-инъекция, а параметры делают её невозможной.

## Миграции и бэкапы

Твои таблицы — тоже код. **Миграции** — небольшие пронумерованные шаги,
которые строят схему и хранятся в git. Alembic пишет их за тебя по моделям
(`alembic revision --autogenerate -m "…"`) и применяет (`alembic upgrade
head`). Каждая база — на твоём ноутбуке, у коллеги, на сервере — получает
одну и ту же схему одним и тем же путём.

<Diagram name="migrations-timeline" />

Вторая половина безопасности данных — бэкап. `pg_dump -Fc` записывает базу
в один файл, `pg_restore` возвращает её обратно. **Бэкап, который ты ни разу
не восстанавливала, — это надежда, а не бэкап.** В Миссии 5 ты его
восстановишь.

## Индексы: каталог библиотеки

Спроси Postgres, как он нашёл ответ:

```sql
EXPLAIN ANALYZE SELECT * FROM documents WHERE source = 'handbook.md';
```

`Seq Scan` значит, что он прочитал все строки — каждую книгу на каждой
полке. `Index Scan` — что он воспользовался каталогом. Индекс по колонке,
по которой ты фильтруешь, превращает секунды в миллисекунды. Индексы
немного замедляют каждую запись, поэтому их ставят там, где ищут, а не
везде.

## Векторы: полки по смыслу

**Эмбеддинг** — это список чисел, который помещает текст на карту смысла.
Тексты с похожим смыслом оказываются рядом, даже если у них нет общих
слов.

<Diagram name="meaning-map" />

pgvector хранит такие списки в колонке и измеряет расстояния:

```sql
CREATE EXTENSION IF NOT EXISTS vector;
CREATE TABLE chunks (
  id bigserial PRIMARY KEY,
  document_id bigint NOT NULL,
  content text NOT NULL,
  embedding vector(384)
);
SELECT id, content FROM chunks ORDER BY embedding <=> :query_vec LIMIT 5;
CREATE INDEX ON chunks USING hnsw (embedding vector_cosine_ops);
```

`<=>` — косинусное расстояние: чем меньше, тем ближе по смыслу. Число `384`
задаёт твоя модель, `intfloat/multilingual-e5-small`. В compose используется
образ `pgvector/pgvector:pg17`: Postgres, в котором pgvector уже есть.

## Redis: стикеры

Некоторая работа медленная, а просят её снова и снова. Redis держит ответ
какое-то время:

```
SET search:money-back "[…]" EX 60
GET search:money-back
TTL search:money-back
```

Этот приём называется **cache-aside**: сначала посмотри на стикер; если
ответ там, отвечай сразу; если нет — сделай настоящую работу и приклей
ответ на 60 секунд.

## Что запомнить

1. **Postgres — источник правды.** Схема меняется только миграциями.
2. **Только параметры.** И `UPDATE` без `WHERE` меняет все строки.
3. **`Seq Scan` по большой таблице? Ищи пропущенный индекс.**
4. **Векторы живут на карте одной модели.** Новая модель — новые эмбеддинги.
5. **В Redis — только то, что можно восстановить. Бэкап считается, только когда его восстановили.**
