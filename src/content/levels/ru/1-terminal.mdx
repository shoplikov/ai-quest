## Где я?

Файлы на Linux-машине складываются в одно большое дерево. Оно начинается с
`/` — корня. Твоя собственная папка — `/home/<твоё имя>`, и у неё есть
короткое прозвище: `~`.

<Diagram name="file-tree" />

Три команды — это твои глаза и ноги:

```bash
pwd          # в какой я комнате?
ls -la       # включить свет: что здесь есть, включая скрытые файлы
cd notes     # перейти в комнату notes
```

Путь, который начинается с `/`, — **абсолютный**: он работает откуда
угодно, как полный почтовый адрес. Путь без него — **относительный**: он
начинается там, где ты стоишь. `.` значит «эта папка», `..` — «папка
выше», поэтому `cd ..` поднимает на одну ступеньку. Если файла «нет»,
сначала проверь `pwd`. Чаще всего с файлом всё в порядке, а ты в другой
комнате.

## Читать и искать

Инструмент для чтения выбирай по размеру файла:

- `cat file` выводит всё сразу — подходит для коротких файлов.
- `less file` даёт листать; выход — `q`.
- `head file` и `tail -n 50 file` показывают начало и последние 50 строк.
- `tail -f file` держит файл открытым и печатает новые строки по мере
  появления. Так смотрят лог вживую.

Искать помогают два охотника: `find . -name "*.py"` ищет файлы **по
имени**, а `grep -rn "text" .` ищет текст **внутри** файлов и сообщает
файл и номер строки.

Главный фокус — пайп (pipe), `|`. Он берёт всё, что напечатала одна
команда, и передаёт следующей, а не на экран:

```bash
ps aux | grep python
```

<Diagram name="pipe" />

`ps aux` перечисляет все процессы — сотни строк. `grep` оставляет те
несколько, что тебе нужны. Маленькие инструменты, соединённые пайпами, —
вот что делает большую часть работы на сервере.

## Кому что можно

Выполни `ls -l` и посмотри на первую колонку:

```
-rwxr-xr-x 1 student student 112 Mar  3 10:42 ticker.sh
```

<Diagram name="permissions" />

После типа идут три группы из `r` (читать), `w` (менять) и `x`
(запускать): для владельца, для группы и для всех остальных. Скрипту нужна
`x`, чтобы его можно было запустить, — `chmod +x script.sh` её добавит.
Некоторые действия касаются всей машины: установка программ, правка
файлов в `/etc`. Для них впереди пишут `sudo` — это значит «попросить от
имени управляющего домом». Он спросит твой пароль. Эта пауза — нарочно.

## Люди в доме: процессы

Каждая запущенная программа — это **процесс** со своим номером, **PID**.
`ps aux` показывает их все, `htop` — вживую, отсортированными по тому,
насколько они заняты (выход — `q`).

- `kill <pid>` просит процесс остановиться. Большинство программ
  прибираются за собой и уходят.
- `kill -9 <pid>` заставляет. Программа не успеет прибраться, поэтому это
  последнее средство, а не первое.
- Команда с `&` в конце работает в фоне и сразу возвращает тебе
  приглашение.

Но есть подвох: фоновые задачи принадлежат твоей сессии. Закроешь окно SSH
— остановятся и они. Для всего долгого — обучения модели, большой
загрузки — есть **tmux**: комната, где свет не гаснет, когда ты уходишь.
Ты выходишь, задача продолжает работать, а позже ты возвращаешься
посмотреть.

## Здоров ли дом?

Четыре команды отвечают на вопросы, которые обычно задают про сервер:

```bash
df -h          # насколько заполнен каждый диск?
du -sh *       # какая из этих папок большая?
free -h        # сколько памяти занято, сколько доступно?
nvidia-smi     # видеокарта и кто её занимает (если она есть)
```

Большинство программ, которые работают постоянно, — это **сервисы**: их
запускает и присматривает за ними systemd. Две команды расскажут их
историю:

```bash
systemctl status nginx       # работает ли? с какого времени?
journalctl -u nginx -f       # его дневник, вживую
```

## Окружение и «command not found»

У каждого шелла есть набор именованных значений — **переменных
окружения**. `export NAME=value` задаёт переменную, `echo $NAME` читает,
`env` показывает все.

Одна из них очень важная: `$PATH`. Это список папок, где шелл ищет
программы. Когда ты набираешь `python3`, шелл проходит по этим папкам по
порядку и запускает первое совпадение. `command not found` значит, что ни
в одной папке из списка такой программы не нашлось. `which python3`
покажет, где шелл её нашёл, — или что не нашёл нигде.

## Другие машины

`ssh user@host` открывает терминал на другой машине. Пароли работают, но
инженеры пользуются **ключами** — парой файлов, созданной на твоём
ноутбуке. Открытый ключ — это замок, который можно раздать всем серверам.
Закрытый ключ — единственный ключ, который этот замок открывает, и он
никогда не покидает твой ноутбук.

Несколько строк в `~/.ssh/config` превращают `ssh student@203.0.113.10` в
`ssh quest`. А `scp file quest:~/` копирует файл на ту сторону.

## Что запомнить

Когда заходишь в тёмный сервер:

1. **Где я и что здесь есть?** → `pwd`, `ls -la`.
2. **Кто дома и всё ли у них хорошо?** → `ps aux`, `systemctl status`, `df -h`, `free -h`.
3. **Что пишет дневник?** → `tail -f`, `journalctl -u`.

Дом казался страшным только потому, что в нём не горел свет. Миссии ниже
его включат.
