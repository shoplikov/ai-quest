  - id: m2
    title: "Смотри лог вживую"
    why: "Ты запускаешь процесс, следишь за тем, что он пишет, и останавливаешь его по PID."
    steps:
      - |
        Открой новый файл в редакторе:
        ```bash
        nano ~/quest/level1/scripts/ticker.sh
        ```
      - |
        Напечатай это, сохрани через Ctrl+O и Enter и выйди через Ctrl+X:
        ```bash
        #!/usr/bin/env bash
        while true; do echo "$(date +%T) tick" >> ~/quest/level1/logs/ticker.log; sleep 2; done
        ```
      - |
        Разреши его запускать и проверь:
        ```bash
        chmod +x ~/quest/level1/scripts/ticker.sh
        ls -l ~/quest/level1/scripts
        ```
        В первой колонке появилась `x`.
      - |
        Запусти его в фоне с `&`:
        ```bash
        ~/quest/level1/scripts/ticker.sh &
        ```
        Шелл напишет номер задачи и PID, например `[1] 4242`, и вернёт тебе приглашение.
      - |
        Смотри, как пишется дневник. Каждые две секунды — новая строка.
        ```bash
        tail -f ~/quest/level1/logs/ticker.log
        ```
        Выйди через Ctrl+C: это останавливает `tail`, а не тикер.
      - |
        Найди тикер среди всех процессов:
        ```bash
        ps aux | grep ticker
        ```
        Вторая колонка — это PID. Одна из строк — сам `grep`, её не считай.
      - |
        Попроси его остановиться — с PID из прошлого шага:
        ```bash
        kill <pid>
        ```
      - |
        Выполни это два раза с паузой в несколько секунд:
        ```bash
        tail -n 3 ~/quest/level1/logs/ticker.log
        ```
    check: "После `kill` последняя строка `ticker.log` не меняется, сколько ни жди."

## Где я?

**Файлы — одно большое дерево. `pwd` говорит, где ты в нём стоишь.**

<Diagram name="file-tree" />

Дерево начинается с `/` — корня. Твоя папка — `/home/<твоё имя>`,
коротко `~`.

```bash
pwd          # в какой я комнате?
ls -la       # включить свет: что здесь есть, включая скрытые файлы
cd notes     # перейти в комнату notes
```

Путь, который начинается с `/`, — **абсолютный**: он работает откуда
угодно. Путь без него — **относительный**: он начинается там, где ты
стоишь. Файла «нет»? Сначала проверь `pwd`.

## Читать и искать

**Инструмент для чтения выбирай по размеру файла, а команды соединяй через `|`.**

- `cat file` выводит всё сразу — для коротких файлов.
- `less file` даёт листать; выход — `q`.
- `head file` и `tail -n 50 file` показывают начало и последние 50 строк.
- `tail -f file` печатает новые строки по мере появления: лог вживую.

`find . -name "*.py"` ищет файлы **по имени**. `grep -rn "text" .` ищет
текст **внутри** файлов и называет файл и номер строки.

Пайп (pipe), `|`, передаёт вывод одной команды следующей:

```bash
ps aux | grep python
```

## Кому что можно

**Скрипт запускается, только если у него есть `x`.**

<Diagram name="permissions" />

Выполни `ls -l` и посмотри на первую колонку:

```text
-rwxr-xr-x 1 student student 112 Mar  3 10:42 ticker.sh
```

Три группы букв: владелец, группа, все остальные. `chmod +x script.sh`
добавит `x`.

<ul class="chips">
  <li><b>r</b> читать</li>
  <li><b>w</b> менять</li>
  <li><b>x</b> запускать</li>
</ul>

<Reveal summary="А что такое sudo?">
Установка программ и правка файлов в `/etc` касаются всей машины. Впереди
пишут `sudo` — «попросить от имени управляющего домом». Он спросит твой
пароль, и эта пауза — нарочно.
</Reveal>

## Люди в доме: процессы

**У каждой запущенной программы есть PID. Фоновые задачи уходят вместе с тобой.**

`ps aux` показывает все **процессы**, `htop` — вживую (выход — `q`).

- `kill <pid>` просит процесс остановиться.
- `kill -9 <pid>` заставляет, прибраться программа не успеет. Последнее
  средство.
- `&` в конце запускает команду в фоне.

Закроешь окно SSH — остановятся и фоновые задачи. Для всего долгого есть
**tmux**: комната, где свет не гаснет, когда ты уходишь.

## Здоров ли дом?

**Четыре команды отвечают на то, что обычно спрашивают про сервер.**

```bash
df -h          # насколько заполнен каждый диск?
du -sh *       # какая из этих папок большая?
free -h        # сколько памяти занято, сколько доступно?
nvidia-smi     # видеокарта и кто её занимает (если она есть)
```

Программы, которые работают постоянно, — это **сервисы**, за ними
присматривает systemd:

```bash
systemctl status nginx       # работает ли? с какого времени?
journalctl -u nginx -f       # его дневник, вживую
```

## Окружение и «command not found»

**`command not found` значит: ни в одной папке из `$PATH` программы нет.**

`$PATH` — это список папок, где шелл по порядку ищет программы.
`which python3` покажет, где шелл её нашёл, — или что не нашёл нигде.

<Reveal summary="Что ещё есть в окружении?">
`$PATH` — одна из **переменных окружения** шелла. `export NAME=value`
задаёт переменную, `echo $NAME` читает, `env` показывает все.
</Reveal>

## Другие машины

**Открытый ключ — замок, его можно раздавать. Закрытый остаётся дома.**

`ssh user@host` открывает терминал на другой машине. Инженеры заходят по
**ключам** — паре файлов, созданной на твоём ноутбуке.

Несколько строк в `~/.ssh/config` превращают `ssh student@203.0.113.10` в
`ssh quest`. `scp file quest:~/` копирует файл на ту сторону.

## Что запомнить

1. **Где я и что здесь есть?** → `pwd`, `ls -la`.
2. **Кто дома и всё ли у них хорошо?** → `ps aux`, `systemctl status`, `df -h`, `free -h`.
3. **Что пишет дневник?** → `tail -f`, `journalctl -u`.
