        ```python
                with engine.connect() as conn:
        ```

        ```python
        import json
        import logging
        import time
        from contextlib import contextmanager
        from contextvars import ContextVar

        request_id: ContextVar[str] = ContextVar("request_id", default="-")
        log = logging.getLogger("quest-api")


        class JsonFormatter(logging.Formatter):
            def format(self, record: logging.LogRecord) -> str:
                line = {
                    "time": self.formatTime(record),
                    "level": record.levelname,
                    "request_id": request_id.get(),
                    "message": record.getMessage(),
                }
                line.update(getattr(record, "data", {}))
                if record.exc_info:
                    line["error"] = self.formatException(record.exc_info)
                return json.dumps(line, ensure_ascii=False)


        def setup_logging(level: str) -> None:
            handler = logging.StreamHandler()
            handler.setFormatter(JsonFormatter())
            logging.basicConfig(level=level, handlers=[handler], force=True)


        @contextmanager
        def timed(stage: str):
            """Log how long one stage of a request took."""
            start = time.perf_counter()
            try:
                yield
            finally:
                ms = round((time.perf_counter() - start) * 1000)
                log.info("stage", extra={"data": {"stage": stage, "ms": ms}})
        ```

        ```python
        @app.middleware("http")

            rid = uuid.uuid4().hex[:8]
            request_id.set(rid)
            start = time.perf_counter()
            response = await call_next(request)
            ms = round((time.perf_counter() - start) * 1000)
            response.headers["X-Request-ID"] = rid
        ```

        ```python
        import statistics
        import sys
        import time
        from concurrent.futures import ThreadPoolExecutor

        import httpx

        URL = sys.argv[1] if len(sys.argv) > 1 else "http://localhost:8000"
        QUESTIONS = [
            "Во сколько открывается кафе?",
            "Можно вернуть деньги через три недели?",
            "Кому идёт заказ KZ-4471?",
            "Овсяное молоко стоит дороже?",
            "У вас есть парковка для гостей?",
        ]


        def ask(i: int) -> tuple[float, bool]:
            start = time.perf_counter()
            try:
                response = httpx.post(f"{URL}/ask", json={"question": QUESTIONS[i % len(QUESTIONS)]}, timeout=120)
                ok = response.status_code == 200
            except httpx.HTTPError:
                ok = False
            return time.perf_counter() - start, ok


        with ThreadPoolExecutor(max_workers=5) as pool:
            results = list(pool.map(ask, range(50)))

        times = sorted(seconds for seconds, _ in results)
        errors = sum(not ok for _, ok in results)
        p50 = statistics.median(times)
        p95 = statistics.quantiles(times, n=20)[-1]
        print(f"p50 {p50:.1f}s  p95 {p95:.1f}s  errors {errors}/{len(results)}")
        ```

## Один код, разные места

Сервис на твоём ноутбуке и сервис на сервере — это один и тот же код.
Всё, чем они отличаются, — адреса, пароли, имена моделей — живёт в
**переменных окружения**. Если обязательной переменной нет, сервис
должен отказаться запускаться и сказать, какой именно: понятная ошибка
на старте лучше странной в три часа ночи.

Секретам в git не место. А git ничего не забывает: секрет, который
закоммитили и потом удалили, остаётся в истории — для всех, кто выполнит
`git log -p`.

## Жив или готов?

Два вопроса — два эндпоинта. `/health` отвечает на вопрос «процесс
жив?». `/ready` — на вопрос «могу ли я делать свою работу?»: доступны ли
база данных и модель. Сервис может быть живым и бесполезным одновременно.

<Diagram name="health-vs-ready" />

Compose этими ответами пользуется: проверка здоровья (`healthcheck`)
говорит ему, как дела у бокса, а `restart: unless-stopped` снова
запускает бокс после падения или перезагрузки.

## Логи, по которым можно искать

Лог — это дневник, а от дневника есть толк, только если в нём можно
найти нужную страницу. Пиши по одной JSON-строке на событие и клади в
каждую **id запроса**: тогда один `grep` покажет весь путь одного
запроса через сервис. И поставь `PYTHONUNBUFFERED=1`, чтобы строки
появлялись сразу, а не порциями.

## Четыре числа

**Метрик** нужно на удивление мало: **частота запросов** (насколько
людно), **доля ошибок** (насколько сломано), **задержка** (насколько
медленно) — а для сервисов с LLM ещё и **токены на запрос** (насколько
дорого). Обычный инструмент здесь — Prometheus; с
`prometheus-fastapi-instrumentator` твой сервис показывает свои числа на
странице `/metrics`.

Для задержки никогда не верь среднему. Смотри на **p50** — обычный
запрос — и на **p95** — ожидание самого невезучего из двадцати.

## Робот-ревьюер

**CI** (continuous integration, непрерывная интеграция) на каждый push
запускает одни и те же проверки: линтер (`ruff check`), тесты (`pytest`)
и сборку образа. Он не устаёт и никуда не торопится. Красный крестик
значит одно: это не деплоить.

## Деплой и откат

В деплое три шага: собрать образ, отправить его, запустить. Давай
каждому образу тег с версией — хеш коммита, а не один только
`latest`, — и ты всегда будешь знать, какой код сейчас работает.

**Откат** — это запуск предыдущего тега. Вчерашнее меню: уже напечатано,
через минуту на столах. Потренируй его до того, как он понадобится.

## Когда всё сломалось

А оно сломается. Сначала **сделай так, чтобы снова работало**, — откат
или перезапуск. И только потом выясняй почему. После напиши короткую
заметку без поиска виноватых: что случилось, кого это задело, в чём была
причина, что мы меняем. Заметка спрашивает, что пропустило ошибку, — и
никогда не спрашивает, кто её сделал.

## Что запомнить

1. **Жив — не значит готов.** `/health` и `/ready` отвечают на разные вопросы.
2. **Один запрос, один id, один `grep`.**

5. **Сначала почини, потом выясняй почему.**
