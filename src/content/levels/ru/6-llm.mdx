        ```python
        import time

        from app.config import settings

        def llm_answer(question: str) -> str:
        ```

        ```python
        def llm_stream(question: str) -> Iterator[str]:
            start = time.perf_counter()
            first_token_ms = None
            out_tokens = 0
            stream = client.chat.completions.create(
                model=settings.llm_model,
                messages=[
                    {"role": "system", "content": load_prompt(ANSWER_PROMPT)},
                    {"role": "user", "content": question},
                ],
                temperature=0.2,
                max_tokens=300,
                stream=True,
                stream_options={"include_usage": True},
            )
            for chunk in stream:
                if chunk.choices and chunk.choices[0].delta.content:
                    if first_token_ms is None:
                        first_token_ms = (time.perf_counter() - start) * 1000
                    yield chunk.choices[0].delta.content
                if chunk.usage:
                    out_tokens = chunk.usage.completion_tokens
            total_ms = (time.perf_counter() - start) * 1000
            log.info(
                "llm stream model=%s out=%d first_token=%.0fms total=%.0fms",
                settings.llm_model, out_tokens, first_token_ms or 0, total_ms,
            )
        ```

        ```python
        import asyncio
        import time

        from openai import AsyncOpenAI

        from app.config import settings

        client = AsyncOpenAI(base_url=settings.llm_base_url, api_key=settings.llm_api_key, timeout=30, max_retries=2)
        limit = asyncio.Semaphore(4)
        in_flight = 0


        async def ask(number: int) -> float:
            global in_flight
            async with limit:
                in_flight += 1
                print(f"start {number:2}  in flight: {in_flight}")
                start = time.perf_counter()
                await client.chat.completions.create(
                    model=settings.llm_model,
                    messages=[{"role": "user", "content": f"Расскажи забавный факт номер {number} о выдрах, одним предложением."}],
                    max_tokens=80,
                )
                seconds = time.perf_counter() - start
                in_flight -= 1
                print(f"done  {number:2}  {seconds:.1f}s")
                return seconds


        async def main() -> None:
            start = time.perf_counter()
            durations = await asyncio.gather(*(ask(n) for n in range(1, 21)))
            print(f"20 calls in {time.perf_counter() - start:.1f}s, slowest {max(durations):.1f}s")


        asyncio.run(main())
        ```

## Как выглядит API

Большинство серверов моделей — vLLM, Ollama и многие другие — говорят на
том же языке, что и API OpenAI. Поэтому один клиент работает со всеми,
меняется только адрес:

```python
from openai import OpenAI

client = OpenAI(base_url=settings.llm_base_url, api_key=settings.llm_api_key)
response = client.chat.completions.create(
    model=settings.llm_model,
    messages=[
        {"role": "system", "content": "Отвечай одним коротким предложением."},
        {"role": "user", "content": "Что такое порт?"},
    ],
    temperature=0.2,
    max_tokens=200,
)
print(response.choices[0].message.content, response.usage)
```

Сообщение **system** задаёт правила, сообщение **user** — это вопрос.
`GET /v1/models` показывает точные имена моделей, которые принимает
сервер. Копируй их, а не угадывай.

## Токены и контекстное окно

Модели читают и пишут **токенами** — кусочками слов. «Выдра» может быть
одним токеном или несколькими; длинное редкое слово — четырьмя. Всё
считается в один общий предел — **контекстное окно**: системный промпт,
документы, вопрос и ответ, который ещё только предстоит написать. Токены
промпта плюс `max_tokens` должны поместиться.

<Diagram name="context-window" />

Каждый ответ сообщает, во сколько он обошёлся, в поле `usage`:
`prompt_tokens` ушло на вход, `completion_tokens` пришло на выходе. И
каждый ответ объясняет, почему остановился, в `finish_reason`: `stop` —
модель закончила, `length` — кончился `max_tokens`, и мысль оборвалась.

Что будет, если не поместилось, зависит от сервера. vLLM отказывает с
кодом `400`. Ollama молча отрезает начало промпта и всё равно отвечает —
и это хуже, потому что тебе никто ничего не сообщает. Узнать об этом
можно, только читая `usage`.

## Стриминг

Модель пишет по одному токену за раз. Без стриминга ты ждёшь последний,
прежде чем увидишь первый. Со стримингом сервер отправляет каждый кусочек,
как только он готов, в виде **server-sent events**: строк, которые
начинаются с `data:`.

Скорость описывают два числа: **время до первого токена** — сколько
пользователь смотрит в пустоту — и **токенов в секунду** после этого. Во
FastAPI `StreamingResponse` передаёт кусочки дальше, по мере того как они
приходят.

## Всё ломается

Сервер модели — это сервис в сети, и ломается он так же: отвечает по
таймауту, выдаёт `429 Too Many Requests`, когда на него слишком давят,
отдаёт `5xx`, пока перезапускается. Давай каждому клиенту `timeout=` и
`max_retries=`. Перед каждой новой попыткой клиент ждёт чуть дольше — и
останавливается, когда предел исчерпан. **Никогда не повторяй
бесконечно**: зависший сервер плюс бесконечные повторы — это пробка,
построенная своими руками.

## Структурированный вывод

Когда ответ читает код, прозы мало. Попроси JSON, который соответствует
схеме, передай схему вместе с запросом (`response_format`), чтобы сервер
держал модель в её рамках, — и всё равно проверь результат через
Pydantic. А потом реши, что делать, если проверка не прошла: одна
повторная попытка, а затем понятная ошибка. Для извлечения ставь
`temperature=0`: нужна одна и та же анкета, заполненная одинаково, а не
творчество.

## Промпты — это код

Промпт меняет поведение сервиса так же, как код. Поэтому он живёт в
файле, в git, с версией в имени: `answer_v1.txt`, `answer_v2.txt`.
Меняй одну вещь за раз и сравнивай результаты на одних и тех же вопросах.
«После правки промпта вроде стало лучше» — это не результат.

## Много запросов разом

Ждать модель — это в основном ждать, та самая работа, что знакома тебе
по циклу событий с уровня 3. С асинхронным клиентом один процесс может
ждать много ответов одновременно. Но у сервера тоже есть пределы, поэтому
на входе ставим вышибалу: `asyncio.Semaphore(4)` пускает внутрь не больше
четырёх вызовов разом.

```python
limit = asyncio.Semaphore(4)

async def ask(question: str) -> str:
    async with limit:
        response = await client.chat.completions.create(...)
        return response.choices[0].message.content
```

## Где живёт модель

Сервер моделей вроде vLLM один раз загружает модель в видеокарту и
обслуживает много клиентов: `vllm serve <model> --port 8000`. Веса модели
занимают большую часть памяти GPU ещё до первого вопроса; `nvidia-smi`
показывает, сколько именно. Чаще всего ты будешь клиентом — но теперь ты
знаешь, что находится по ту сторону порта.

## Что запомнить

1. **Промпт плюс `max_tokens` должны поместиться в окно.** Читай `usage`.
2. **Проверяй `finish_reason`.** `length` значит «не закончено».
3. **У каждого вызова есть таймаут и предел повторов.** Никогда не повторяй бесконечно.
4. **Никогда не доверяй JSON от модели без валидации.**
5. **Задержка — это два числа:** время до первого токена и токены в секунду.
