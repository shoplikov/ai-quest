  text: >
    Образ — это рецепт и собранный бокс, который ждёт в морозилке.
    Контейнер — один бокс, который достали и открыли. Внутри у бокса свой
    маленький мир: свои файлы, свой `localhost`. Том (volume) — это полка на
    настоящей кухне, которой бокс может пользоваться, поэтому еда остаётся,

    title: "Собери ланч-бокс"
    why: "Ты кладёшь `quest-api` в бокс, которому не нужен Python с твоего ноутбука."
    steps:
      - do: |
          Проверь, что Docker работает:
          ```bash
          docker run --rm hello-world
          ```
        fail: "`permission denied` про сокет Docker? Попроси ментора добавить тебя в группу `docker`, потом выйди из системы и зайди снова."
      - |
        С активным venv обнови список покупок:
        ```bash
        pip freeze > requirements.txt
        ```
      - |
        Напиши `Dockerfile` в папке проекта:
        ```dockerfile
        FROM python:3.12-slim
        WORKDIR /app
        COPY requirements.txt .
        RUN pip install --no-cache-dir -r requirements.txt
        COPY . .
        CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
        ```
      - |
        Напиши `.dockerignore`, чтобы бокс был маленьким, а секреты остались снаружи:
        ```text
        .venv
        .git
        __pycache__
        .env
        ```
      - |
        Собери образ:
        ```bash
        docker build -t quest-api .
        ```
        Смотри, как проходят шаги: по одному на каждую строку Dockerfile.
      - |
        Запусти из него бокс:
        ```bash
        docker run --rm -p 8000:8000 quest-api
        ```
      - |
        В другом терминале выйди из venv и вызови сервис:
        ```bash
        deactivate
        curl -s localhost:8000/health
        ```
        Свой Python бокс принёс с собой.
    check: "`curl -s localhost:8000/health` выводит `{\"status\":\"ok\"}`, хотя ни один venv не активен."

    title: "Быстрые пересборки"
    why: "Ты с секундомером видишь, почему порядок строк в Dockerfile важен."
    steps:
      - |
        Сделай медленную копию своего Dockerfile — `Dockerfile.slow`. В ней код копируется раньше, чем ставятся пакеты:
        ```dockerfile
        FROM python:3.12-slim
        WORKDIR /app
        COPY . .
        RUN pip install --no-cache-dir -r requirements.txt
        CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
        ```
      - |
        Собери её один раз, чтобы наполнить кэш:
        ```bash
        docker build -f Dockerfile.slow -t quest-api:slow .
        ```
      - "Поменяй одну строку кода, например текст в `fake_answer`."
      - |
        Пересобери с секундомером:
        ```bash
        time docker build -f Dockerfile.slow -t quest-api:slow .
        ```
        Заметь: `RUN pip install` выполняется заново.
      - |
        Поменяй строку ещё раз и пересобери своим хорошим Dockerfile:
        ```bash
        time docker build -t quest-api .
        ```
        Найди слово `CACHED` рядом с шагом `pip install`.
      - "Сравни два времени. Потом удали `Dockerfile.slow`."
    check: "При хорошем порядке пересборка занимает секунды, и ты можешь объяснить почему одним предложением."
  - id: m4
    title: "Два бокса"
    why: "Ты запускаешь API рядом с настоящей базой данных, и API проверяет, что может до неё достучаться."
    steps:
      - |
        Добавь драйвер PostgreSQL:
        ```bash
        pip install "psycopg[binary]"
        pip freeze > requirements.txt
        ```
      - |
        В `app/config.py` добавь в `Settings` одно поле:
        ```python
        database_url: str = "postgresql://postgres:postgres@localhost:5432/postgres"
        ```
      - |
        Добавь проверку готовности в `app/main.py`:
        ```python
        @app.get("/ready")
        def ready():
            try:
                with psycopg.connect(settings.database_url, connect_timeout=2) as conn:
                    conn.execute("SELECT 1")
            except psycopg.OperationalError as error:
                log.warning("database not ready: %s", error)
                raise HTTPException(status_code=503, detail="database not reachable")
            return {"status": "ready"}
        ```
        Наверху файла нужны `import psycopg` и импорт `HTTPException`.
      - |
        Добавь две строки в `.env`. Пароль придумай свой.
        ```text
        POSTGRES_PASSWORD=change-me
        DATABASE_URL=postgresql://postgres:change-me@db:5432/postgres
        ```
      - "Те же ключи, но без настоящего пароля, добавь в `.env.example`."
      - |
        Напиши `compose.yaml`. У `api` своя проверка здоровья (healthcheck), чтобы было видно, что оба бокса в порядке:
        ```yaml
        services:
          api:
            build: .
            ports: ["8000:8000"]
            env_file: .env
            depends_on:
              db:
                condition: service_healthy
            healthcheck:
              test: ["CMD", "python", "-c", "import urllib.request; urllib.request.urlopen('http://localhost:8000/health')"]
              interval: 5s
              retries: 5
          db:
            image: postgres:17
            environment:
              POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
            volumes: ["pgdata:/var/lib/postgresql/data"]
            healthcheck:
              test: ["CMD-SHELL", "pg_isready -U postgres"]
              interval: 5s
              retries: 10
        volumes:
          pgdata:
        ```
      - |
        Запусти оба:
        ```bash
        docker compose up -d --build
        ```
      - |
        Подожди несколько секунд и проверь:
        ```bash
        docker compose ps
        ```
        Обе строки кончаются на `(healthy)`.
      - |
        Спроси API:
        ```bash
        curl -s localhost:8000/ready
        ```
        Ответ: `{"status":"ready"}`.
      - |
        Останови базу и спроси снова:
        ```bash
        docker compose stop db
        curl -s localhost:8000/ready
        ```
        Теперь ответ — 503.
      - |
        Лог объяснит почему:
        ```bash
        docker compose logs api
        ```
      - |
        Запусти базу обратно:
        ```bash
        docker compose start db
        ```
    check: "`docker compose ps` показывает оба сервиса здоровыми, `/ready` отвечает 200, а с остановленной базой — 503."

        ```bash
        docker volume ls
        ```

      - |
        Верни всё и дождись healthy:
        ```bash
        docker compose up -d
        ```
      - |
        Посмотри:
        ```bash
        docker compose exec db psql -U postgres -c "SELECT * FROM notes;"
        ```
        Твоя строка на месте.
      - |
        А теперь осторожно и только на этом учебном проекте:

        ```bash
        docker compose down -v
        ```

breaks:
  - id: b1
    title: "Только для своих — в боксе"
    do: |
      Запусти бокс с приложением на 127.0.0.1:
      ```bash
      docker run --rm -p 8000:8000 quest-api uvicorn app.main:app --host 127.0.0.1 --port 8000
      ```
      В другом терминале:
      ```bash
      curl localhost:8000/health
      ```
    see: "curl: (56) Recv failure: Connection reset by peer"
    why: "Внутри бокса 127.0.0.1 — это сам бокс. Дверца Docker приводит твой стук снаружи бокса, а там никто не слушает. Это «только для своих» из уровня 2 — на этаж глубже."
    fix: "Слушай `--host 0.0.0.0`, как уже делает `CMD` в твоём Dockerfile."
  - id: b2
    title: "Бокс, который сразу закрывается"
    do: |
      Запусти бокс с опечаткой в имени модуля:
      ```bash
      docker run -d --name broken quest-api uvicorn app.mian:app --host 0.0.0.0
      ```
      Поищи его. Первая команда его не покажет, вторая покажет:
      ```bash
      docker ps
      docker ps -a
      ```
    see: "Exited (3) 2 seconds ago"
    why: "Контейнер живёт ровно столько, сколько его главный процесс. Процесс завершился с ошибкой — и бокс закрылся. Docker не гадает почему: программа сама сказала это в логах."
    fix: "`docker logs broken` показывает `Error loading ASGI app. Could not import module \"app.mian\".` Исправь имя и убери мёртвый бокс: `docker rm broken`. Когда бокс умирает, первым делом — логи. Всегда."
  - id: b3
    title: "Какой localhost?"
    do: |
      В `.env` замени `@db:5432` на `@localhost:5432`. Потом выполни:
      ```bash
      docker compose up -d
      curl -s localhost:8000/ready
      docker compose logs api
      ```
    see: "connection failed: connection to server at \"127.0.0.1\", port 5432 failed: Connection refused"
    why: "`localhost` внутри бокса API — это бокс API. Никакой базы там нет. Внутри compose до каждого бокса добираются по имени сервиса."
    fix: "Верни `@db:5432` и снова выполни `docker compose up -d`. `/ready` отвечает 200."
  - id: b4
    title: "Дверь уже занята"
    do: |
      Пусть работает бокс из Миссии 2:
      ```bash
      docker run -d --rm --name quest -p 8000:8000 quest-api
      ```
      Запусти второй на ту же дверь:
      ```bash
      docker run --rm -p 8000:8000 quest-api
      ```
    see: "Bind for 0.0.0.0:8000 failed: port is already allocated"
    why: "Порт 8000 на твоей машине — одна дверь, и её уже занял первый бокс. Внутри оба бокса могли бы слушать 8000 — проблема только в левой части `-p`."
    fix: "`docker ps` покажет, кто занял дверь. Останови его через `docker stop quest` или дай второму боксу другую дверь: `-p 8001:8000`."
traps:
  - error: "port is already allocated"
    meaning: "Этот порт на твоей машине уже держит другой контейнер или программа."
    firstMove: "`docker ps`, потом `ss -tlnp | grep :<порт>`"
  - error: "Exited (1) или любое число, кроме 0"
    meaning: "Главный процесс завершился с ошибкой, поэтому остановился и контейнер."
    firstMove: "`docker logs <имя>`"
  - error: "Exited (137)"
    meaning: "Процесс убили снаружи — обычно за то, что он съел слишком много памяти. 137 — это 128 + 9: сигнал 9, тот самый, который не спрашивает."
    firstMove: "`docker stats`, пока он работает; дай ему больше памяти или сделай так, чтобы ему хватало меньшего."
  - error: "failed to compute cache key: … \"/requirements.txt\": not found"
    meaning: "`COPY` не нашёл файл: он лежит вне папки сборки, или его исключает `.dockerignore`."
    firstMove: "Проверь и то и другое: откуда ты запускаешь `docker build` и что в `.dockerignore`."
  - error: "Cannot connect to the Docker daemon"
    meaning: "Docker не запущен. (Если вместо этого написано `permission denied`, ты не в группе `docker`.)"
    firstMove: "`sudo systemctl status docker`; `groups` покажет, есть ли ты в `docker`."
  - error: "exec format error"
    meaning: "Образ собран для процессора другого типа. Процессору дали книгу на языке, которого он не учил, и он сообщает об этом очень официально."
    firstMove: "Собери под процессор сервера: `docker build --platform linux/amd64 …`"
  - error: "Моих изменений нет в контейнере"
    meaning: "Контейнер работает на старом образе. Образ не пересобран."
    firstMove: "`docker compose up -d --build`"

## Отправь машину целиком

**Образ — собранный бокс. Контейнер — один открытый бокс.**

<Diagram name="image-vs-container" />

Ты один раз пишешь рецепт в `Dockerfile`. `docker build` собирает
**образ** (image): твой код, Python и все пакеты, замороженные.
`docker run` открывает один бокс — **контейнер** (container). Боксов
может быть сколько угодно, на любом сервере.

## Dockerfile по строчкам

**Каждая строка — слой. Медленные и стабильные строки идут первыми.**

```dockerfile
FROM python:3.12-slim                  # начать с маленького бокса с Python
WORKDIR /app                           # работать в /app внутри бокса
COPY requirements.txt .                # принести список покупок
RUN pip install -r requirements.txt    # купить всё по списку
COPY . .                               # принести свой код
CMD ["uvicorn", "app:app", "--host", "0.0.0.0", "--port", "8000"]
```

Docker запоминает **слои** (layers) — это кэш сборки. При пересборке он
берёт из кэша все слои до первого, у которого изменились входные данные.
Начиная с него всё собирается заново.

## Собери, запусти, загляни внутрь

**Пяти команд хватает на всю жизнь бокса.**

```bash
docker build -t quest-api .                 # приготовить по рецепту
docker run --rm -p 8000:8000 quest-api      # открыть бокс
docker ps                                   # какие боксы работают?
docker logs -f <имя>                        # что он говорит?
docker exec -it <имя> sh                    # открыть бокс и заглянуть внутрь
```

<Reveal summary="Что не попадает в бокс?">
Файл `.dockerignore` не пускает в бокс `.venv` (у бокса свои пакеты),
`.git`, кэши и `.env` с твоими секретами. Маленький бокс быстрее
собирается, и утекать из него нечему. Базовый образ `-slim` тоже помогает.
</Reveal>

## Порты — на этаж глубже

**Слева — твоя машина, справа — бокс.**

`-p 8000:8000` прорезает в боксе дверцу. Внутри бокса `127.0.0.1` — это
сам бокс, как в уровне 2. Гости приходят снаружи, поэтому приложение
должно слушать `0.0.0.0`.

<Reveal summary="Что значит -p 8080:8000?">
«Дверь 8080 на моей машине ведёт к двери 8000 в боксе»
</Reveal>

## Данные живут на полке

**Удалишь бокс — его файлы пропадут. Том останется.**

<Diagram name="volume" />

Контейнеры одноразовые: новый бокс всегда чистый. Но база данных забывать
не должна. Всё ценное хранится в **томе** (volume) — на полке настоящей
кухни.

## Compose: боксы, которые знают друг друга

**Один файл описывает все боксы. Одна команда запускает их вместе.**

<Diagram name="compose-network" />

Настоящий сервис — это несколько боксов: API, база данных, потом кэш.

```yaml
services:
  api:
    build: .
    ports: ["8000:8000"]
    env_file: .env
    depends_on:
      db:
        condition: service_healthy
  db:
    image: postgres:17
    environment:
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
    volumes: ["pgdata:/var/lib/postgresql/data"]
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 5s
      retries: 10
volumes:
  pgdata:
```

Боксы живут в одной сети и находят друг друга **по имени сервиса**. API
обращается к базе по адресу `db:5432` — и никогда не по `localhost:5432`:
это собственный бокс API.

Команды на каждый день:

```bash
docker compose up -d --build    # запустить и пересобрать то, что изменилось
docker compose logs -f api
docker compose ps
docker compose exec api sh
docker compose down
```

> ⚠️ `docker compose down -v` удаляет ещё и тома — а с ними данные твоей
> базы. На настоящем проекте остановись и перечитай команду дважды.

## Что запомнить

1. **Образ — рецепт и собранный бокс. Контейнер — один открытый бокс.**
2. **Медленные и стабильные строки — первыми, твой код — последним.** Тогда пересборка занимает секунды.
3. **Внутри бокса `localhost` — это бокс.** Слушай `0.0.0.0`, а к другим боксам обращайся по имени сервиса.
4. **Ценные данные живут в томе.** А `down -v` их удаляет.
