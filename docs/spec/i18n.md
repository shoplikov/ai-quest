# Two languages: English and Russian

The whole site exists in English (`en`) and Russian (`ru`). This file
overrides the other specs wherever they assume one language.

## Routes

Every page lives under a language prefix:

```
/en/            /ru/
/en/level/2     /ru/level/2
/en/boss        /ru/boss
/en/skills      /ru/skills
/en/glossary    /ru/glossary
/en/cheatsheets/2   /ru/cheatsheets/2
/en/mentor      /ru/mentor
```

Use Astro's built-in i18n routing with both locales prefixed (look up the
current config in the Astro docs).

`/` is a tiny static page that picks a language and redirects with
JavaScript, in this order: saved choice → browser language (`ru*` → `ru`)
→ `en`. It keeps any `#p=…` share hash when it redirects. Inside
`<noscript>` it shows two plain links: "English" and "Русский".

`/404.html` is one page with both languages on it (the server cannot know
which one the visitor wants): Porto, the English line, the Russian line,
and two buttons to the two maps.

## Language switcher

In the top navigation: a two-option control "EN | RU". It goes to the
same page in the other language, keeps the scroll position's section
anchor if there is one, and saves the choice in `localStorage` under
`aiquest:lang` (separate from progress, wrapped in try/catch).

## Progress is shared between languages

Progress stores only ids and indexes, never text, so it is the same in
both languages. For that to hold, the two versions of a level must match
exactly in structure. Add a Vitest test (`tests/content-parity.test.ts`)
that fails if, for any level, the `en` and `ru` files differ in:

- `id`, `slug`, `weeks`, `landmark`, badge `emoji`;
- the list of mission ids, and the number of steps in each mission;
- the list of break ids;
- the number of traps, self-check items, links and cheat-sheet rows;
- the `cmd` value of each cheat-sheet row (commands are never translated),
  unless the level sets `cheatsheetKind: notes` (rows are plain words);
- quiz length, the number of options per question, and each `answer` index;
- the `code` value of each quiz question and the `see` value of each
  break (real error output stays in English), unless that break sets
  `seeKind: description` in both files: then `see` describes behaviour in
  words and is written in each language;
- the list of widgets and diagram names used in the body.

The glossary has the same kind of test: same terms, same order, same levels.

A share link opens in the language of the person who opens it, not the
person who made it: the link is `/<lang>/#p=…`, and `/` + `#p=…` also works.

## Where text lives

| Text | Place |
|------|-------|
| Level content | `src/content/levels/en/<id>-<slug>.mdx` and `src/content/levels/ru/<id>-<slug>.mdx` |
| Glossary | `src/content/glossary/en.yaml`, `ru.yaml` (`ru` adds a field `en: "<English term>"`, shown in brackets after the Russian term) |
| Interface strings (navigation, buttons, section titles, toasts, dialogs, rank titles, extra badge names, home and boss copy) | `src/i18n/en.ts` and `src/i18n/ru.ts`, one typed dictionary; a missing key in `ru` is a type error |
| Widget text | In the same dictionaries, under a key per widget. Widgets get their strings as a prop from the Astro page; they never import a language file by themselves. Pure logic functions return codes (`stopAt`, rule ids), and the view maps codes to text |
| Porto's lines | `src/data/porto.en.ts`, `porto.ru.ts` — same pools, same number of lines |
| Boss, skills intro, mentor guide | Content files per language, built from `docs/spec/extras.md` |
| Diagram labels | Passed to the diagram component from the dictionary. No text baked into shared SVG paths |

No string that a visitor reads may be written directly in a component.

## Formatting

- `<html lang>` is set per page; add `hreflang` alternate links.
- Numbers and dates: `Intl.NumberFormat` and `Intl.DateTimeFormat` with
  the page language (certificate date, "finished on").
- Plurals: use `Intl.PluralRules`. Russian needs three forms:
  1 неделя / 2 недели / 5 недель; 1 миссия / 2 миссии / 5 миссий;
  1 день / 2 дня / 5 дней. Put the forms in the dictionary.
- Layout: Russian text is often 15–25% longer. Buttons, pills, map labels
  and the side contents list must wrap or grow; test both languages at 360px.

## Fonts

Fredoka has no Cyrillic letters, so it is not used. Both languages use:

- Headings and body: **Nunito Variable** (`@fontsource-variable/nunito`),
  headings at weight 800, body at 400 and 700.
- Code: **JetBrains Mono Variable**.

Load the Latin and Cyrillic subsets of both.

## Russian voice

`src/content/levels/ru/2-ports.mdx` is the finished example. Match it.

- Address the learner as **«ты»**, warmly. She is one specific person, so
  verbs and adjectives about her are in the feminine form («ты
  написала», «сама находишь»). Keep that consistent everywhere.
- Write Russian, do not translate English word by word. Rebuild the
  sentence the way a kind Russian-speaking senior would say it. Jokes may
  change as long as they stay about the technology and stay kind.
- Use «ё». Use «…» guillemets for quotes. Use an em dash with spaces.
- Never translate: commands, flags, file names, code, real error
  messages, HTTP status texts, product names.
- Banned in Russian too: «просто», «легко», «очевидно», «элементарно»,
  «всего лишь» when they belittle the task.
- Links: prefer a Russian page of the same official source when one
  exists and is current (as with the nginx guide); otherwise keep the
  English link and say «на английском» in its description.

### Analogies in Russian (keep them the same across levels)

- machine = многоквартирный дом; port = дверь; firewall = охранник на входе;
  reverse proxy = администратор у входа; tunnel = личный коридор
- server in the dark = дом с выключенным светом; tmux = комната, где свет не гаснет
- API = ресторан; endpoint = блюдо в меню; status code = выражение лица официанта;
  event loop = один официант на много столиков
- container = ланч-бокс; image = рецепт и собранный бокс в морозилке;
  volume = полка на настоящей кухне
- Postgres = библиотека со строгим библиотекарем; Redis = стикеры на мониторе;
  embeddings = полки, расставленные по смыслу
- LLM = гениальный шеф с маленьким столом; token = кусочек; context window = стол
- RAG = экзамен с открытой книгой; retriever = помощник, который бегает за страницами
- production = открыть кафе, а не готовить дома; rollback = вчерашнее меню
